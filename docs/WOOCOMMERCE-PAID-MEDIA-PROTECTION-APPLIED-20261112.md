# 432 — продукционна защита на платените WooCommerce записи (12.11.2026)

**Реално изпълнено:** 22/22 преди това публично достъпни оригинални платени аудиофайла са блокирани за директни анонимни заявки.

- На Everest са създадени точно **два** файла `.htaccess` в определените директории на WordPress uploads. В тях са активирани две правила `FilesMatch`, насочени **само** към 22-те оригинални имена. Преди операцията двата файла `.htaccess` не са съществували.
- След операцията **44/44 HTTPS заявки** (22 файла × два домейна) получават **HTTP 403** вместо предишните HTTP 206.
- Другите **4** оригинални платени WAV файла вече са били защитени с HTTP 403.
- Изходните аудиофайлове, настройките на WooCommerce, базата с поръчките, основният `.htaccess`, DNS и WordPress core не са променяни.
- Основният сайт, `/bg/`, сайтът на фондацията и 432 Project продължават да връщат HTTP 200.
- Скриптът за прилагане запазва възможност за точково връщане назад при отделно разрешение. Не се допуска автоматичен rollback, защото той отново би изложил платените записи.

**Кодова съвместимост:** WooCommerce 7.0.2 използва `force` за файлови изтегляния, `redirect fallback=no`, а PHP може да прочете 26/26 оригинални аудиофайла локално. **Не е доказано с реално клиентско разрешение**, че всички исторически купувачи все още получават изтеглянията. Не бива да се твърди, че това условие е окончателно затворено.

**Статус на миграцията:** `excludedMediaAndUnreviewedFilesDenylistValidated=false`, защото освен защитата на 26-те исторически платени файла условието включва и останалите непубликувани материали, клиентското обслужване и бъдещата Apache конфигурация при Astro cutover.

Няма изключване или премахване на WordPress/WooCommerce и няма изменение на клиентски права. Подробните оригинални пътища и правилата с реалните имена остават **само в защитената непублична папка на Everest**, не в този документ и не в GitHub.
